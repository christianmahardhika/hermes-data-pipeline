⚙️ Processing Pipeline

  • Collect

    Fetch RSS → Retry with backoff → Fallback URLs → Circuit breaker

  • Clean

    Strip HTML (ammonia) → Normalize → SHA256 dedup

  • Label

    Prof Jiang Game Theory via LLM → actors, events, signals

  • Embed

    TEI (multilingual-e5-base) → 768-dim vectors

  • Ingest

    ArangoDB graph (articles, actors, edges) + near-dup detection

Bagaimana Mereka Berhubungan?

Ini BUKAN service terpisah!

Semua modul (cleaners, labelers, embedders) adalah fase sequential dalam 1 binary Rust yang sama (cargo run). Data mengalir: Collect → SQLite → Clean → SQLite → Label → SQLite → Embed → ArangoDB

ModuleTugasDependencyOutput
collectors/mod.rs Fetch data dari sources (RSS, API) Network only Raw articles → SQLite (status: pending)
cleaners/mod.rs Bersihkan HTML, normalize text, deduplicate Tidak perlu service luar Clean text → SQLite (status: processed)
labelers/mod.rs Analisis game theory (actors, events, signals) → Kiromania LLM (:9000) JSON labels → SQLite (status: labeled)
embedders/mod.rs Ubah text → vector 768-dim untuk similarity search → TEI Server (:8082) Vectors + metadata → ArangoDB (status: ingested)

🔑 Key Insight:

  • cleaners = text processing (lokal, cepat, tanpa network)
  • labelers = AI analysis (butuh LLM API, lambat, mahal)
  • embedders = vectorization (butuh TEI server, untuk similarity search nanti)
  • SQLite sebagai "staging area" antar fase — kalau 1 fase gagal, fase sebelumnya tidak perlu diulang

🧠 Prof Jiang Game Theory Framework

Setiap artikel dianalisis sebagai "strategic move" dalam papan geopolitik/ekonomi:

👥 Actors

Key players (governments, companies, individuals) with incentives & constraints

📅 Events

What happened, trigger, significance, tense (past/present/future)

🔗 Relations

Power dynamics, alliances, conflicts between actors

🌍 Context

Geopolitical, economic, social background factors

🔄 Pattern Match

Historical parallels (trade_war, currency_crisis, etc.)

📈 Investment Signal

bullish / bearish / neutral / hold / defensive + confidence

REFACTOR PROPOSAL

❌ Current (2 services)

  • • Rust API (:8888) — REST endpoints
  • • Rust WebSocket (:8889) — real-time
  • • Next.js (:3000) — separate frontend
  • → 2 Docker images, separate deploy

✅ Proposed (1 monolith)

  • • Next.js fullstack (:3000)
  • • API Routes = BFF (langsung query ArangoDB)
  • • Server Actions for mutations
  • • WebSocket via Next.js middleware
  • → 1 Docker image, lightweight, single deploy
Stack OptionSizeProCon
Next.js 16 ~200MB image Already exists (nextjs-intelligence-dashboard/), RSC, streaming Node.js runtime overhead
SvelteKit ~80MB image Smaller, faster, simpler Rewrite needed, smaller ecosystem
Rust (Leptos/Axum) ~30MB image Smallest, already Rust stack SSR Rust is still immature, slower DX

Recommendation: Next.js monolith — sudah ada scaffolding, ArangoDB driver ada (arangojs), dan BFF pattern cukup mature. Single docker build → single image (:3000). Remove Rust API (:8888/:8889) setelah semua endpoint di-port ke Next.js API Routes.
